API testing with data generation:
Mo phong lai API test cua cty Avepoint - EduTech prj.

1. Happy case:
- Input: 
    1. Data generated by tool.
    2. Data input by human.
- Output: 
    1. Data created successfully and show on UI.
    2. If error, export data with detail error and status to excel file, and not import to system.
    3. Detail report for data validation and API testing.
- Action: 
    1. Define necessary data: empty data, value list, length, range, format, ...
    2. Build data specification (excel file) base on requirements in step 1.
    3. Build data template (excel file), with column names are neccessary fields of request body to create data.
    4. Build request body template for create/edit/get data as json data.
    5. Prepare data to data template.
    6. Read data from data template file
    7. Data preprocessing (mapping, cleaning, separate by separator,...). 
    8. Data validation, if pass, show validation status = Pass, else Fail, and export detail error with format [Column name][Error type] Error message. Error data not import to UI. => data validation report
    9. Data import successfully will display correct on UI, and show import status = Pass, else show import status = Fail, and export detail error with format [HTTPS status code] Text response. => data validation report
    10. API testing: Having expected result and actual result, ex: Expected result: status_code == 200, name = "A". Actual result: status_code == 200, name = "A". => the same: API test result: Pass, else Fail => API test error detail
    11. Data summarize: total processing time, num of pass, num of fail, validation fail, import fail. => to excel/pdf/word file, for each type: data validation and API test.
    
- Negative case: Almost the same as happy case, except for these steps:
    1. Define invalid data and cases.
    8. Data validation: no need
    9. Data import result: All fail. If pass, it's error => validation status = Fail, error message detail.
    10. API testing: Insert expected result and actual result. For example, expected result: status_code == 400, message: Name must be string. Actual result: status_code == 400, message: Name must be string. Compare expected result and actual result => write actual result, validation status = Pass if the same, else Fail, and show detail error message.
    11. Summarize: total processing time, num of passed cases, num of failed cases, pass ratio, detail id/name/index failed case for each type: data validation and API test.
